# 参考渲染器用 Canvas 2D 绘制清单

参考渲染器分两层：先把界面规格和资产清单变成一份纯数据的绘制清单（图片、九宫、着色、文字、占位），再由一份只依赖 Canvas 2D 接口的执行代码画出来。门禁在 Node 里用 `@napi-rs/canvas`（Skia）无界面出图；Studio 在网页里用浏览器自带的 Canvas，执行的是同一份清单、同一份代码。方案 §15 原定的 PixiJS 推迟到需要 Spine 骨骼动画时再评估。

M1 的门禁要的是三样东西：用项目字体画出带描边和阴影的文字，九宫拉伸与乘色着色，以及显隐测试那样一次渲染几百帧。2026-11-26 在本机实测：中文描边、阴影、九宫、着色都正确，单帧编码约 7 毫秒，系统字体可用，项目字体可以按文件注册。

## 考虑过的方案

- **PixiJS，在无头浏览器里运行**：有官方 Spine 运行时，但门禁每次都要起浏览器，取像素要跨进程传图；字体要通过网页加载。M1 用不到它的动画能力。
- **sharp 合成，文字用 SVG**：不用新依赖，但 librsvg 的文字描边、阴影和自定义字体文件都不好控制，和 Studio 的网页渲染也不是同一份代码。

## 后果

- 门禁不依赖浏览器，速度快，结果在同一台机器上可复现。
- 绘制清单是 Studio 和门禁之间的契约；新增一种基元的画法，两边同时生效。
- Skia（Node）与 Chromium（Studio）的文字光栅化有细微差异，所以保真度量只以 Node 端出图为准。
- 到 M2 接入 Spine 时，可以给绘制清单加一种“动画位”操作，由 PixiJS 或 Spine 的 Canvas 运行时执行，不影响已有的门禁。
